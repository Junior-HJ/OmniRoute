- **fix(providers):** a failed Codex client-version refresh no longer disappears silently. `refreshCodexClientVersion()` swallowed every failure with a bare `catch {}`, so a deployment whose egress blocks `registry.npmjs.org` kept advertising the pinned `DEFAULT_CODEX_CLIENT_VERSION` with no log, no counter and no surfaced state — the live `/backend-api/codex/models` catalog simply came back short and nothing explained why (#16714). The refresh now warns once per failed attempt with the concrete reason (thrown error message, non-ok HTTP status, schema mismatch, or a registry version older than the current one) and records which source the next upstream call will use: `override` (`CODEX_CLIENT_VERSION`), `registry` (npm metadata applied) or `fallback` (last refresh failed). `getCodexClientVersionSource()` exposes it, and the Codex discovery response now carries `discovery.clientVersion = { version, source, degraded? }` so an operator can see a degraded catalog from the API instead of inferring it from missing models. Behaviour is otherwise unchanged: failures still fall back to the last-known-good version and are still retried after the bounded delay.
